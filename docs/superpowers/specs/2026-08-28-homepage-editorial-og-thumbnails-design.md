# AI Digest 首頁編輯雜誌風與完整 OG 縮圖設計

## 目標

為摘要首頁建立三種風格差異明顯的獨立 HTML mockup，供視覺比較；使用者已選定 A「編輯雜誌風」作為後續正式首頁的設計方向。

本次 mockup 的核心要求是讓每張 OG 圖以完整縮圖呈現，不得使用裁切方式填滿容器。mockup 僅供設計確認，不直接修改 Astro 正式首頁、摘要資料格式或後端流程。

## 已比較方案

### A：編輯雜誌風（已選定）

- 暖白紙張底色、深墨色文字與磚紅色重點色。
- 襯線標題搭配無襯線內文，建立編輯台與長篇閱讀感。
- 首屏為「本期精選」，左側呈現摘要資訊，右側呈現完整 OG 圖。
- 精選區下方使用留白充足、細框分隔的摘要卡片網格。

### B：深色策展藝廊

- 深色背景、鮮明強調色與較高的圖片視覺比重。
- 以策展牆與內容收藏庫為意象。
- 適合強調視覺探索，但不是本次採用方向。

### C：知識儀表板

- 側欄、統計摘要與緊湊橫列組成資訊密度較高的介面。
- 適合大量內容管理與快速掃描。
- 功能感較強，但不是本次採用方向。

## A 方案版面

### 頁首

- 保留 AI Digest 品牌、搜尋與分類導覽。
- 搜尋、分類篩選及日期排序沿用現有行為。
- 導覽與主要內容採一致的頁面最大寬度與左右留白。

### 本期精選

- 使用最新一筆 `published` 摘要作為精選內容。
- 桌面版採左右雙欄：左側顯示分類、標題、摘要、日期與來源；右側顯示 OG 圖。
- 小螢幕改為單欄，文字在前、圖片在後。
- 整個精選內容可導向摘要詳情頁。

### 摘要卡片

- 桌面版三欄、平板版兩欄、手機版單欄。
- 卡片包含完整 OG 縮圖、分類、標題、摘要節錄、日期與來源。
- 使用細邊框與留白分隔內容，不使用厚重陰影。
- 手機版可以縮短摘要節錄，但不得省略標題、OG 圖、分類、日期及來源。

## OG 圖顯示規則

- 圖片展示框維持 `1200:630`（約 `1.9048:1`）長寬比。
- 圖片使用 `width: 100%`、`height: 100%` 與 `object-fit: contain`。
- 圖片在容器中水平及垂直置中，禁止使用 `cover` 或其他會裁切內容的呈現方式。
- 圖片尺寸或比例不足時，以低彩度背景或留白補足，不拉伸、不變形。
- 為圖片框預留固定比例，避免圖片載入導致版面位移。
- 圖片載入失敗時，顯示帶有來源名稱的預設占位區。

## 視覺語言

- 背景使用暖白色，主要文字使用深墨色，互動與分類重點使用磚紅色。
- 標題使用具編輯感的襯線字體；摘要、日期與控制元件使用清晰的無襯線字體。
- 分類以小型標籤顯示；日期與來源降低視覺層級。
- 卡片 hover 僅提高邊框對比並輕微上移，避免動畫干擾閱讀。
- 字型應使用可靠的系統或既有網站字型組合，mockup 不依賴外部字型服務才能成立。

## 互動與無障礙

- 摘要卡片整體可點擊，並可透過鍵盤聚焦及開啟詳情頁。
- 焦點狀態必須清楚可見。
- OG 圖以摘要標題作為替代文字；裝飾性占位背景不重複朗讀。
- 文字、標籤、連結與操作元件需維持足夠色彩對比。
- 搜尋、分類篩選與日期排序不得因視覺改版而改變既有語意或操作方式。

## 資料與架構界線

- mockup 可使用現有已發布摘要作為代表資料，但不得寫回或改變摘要 JSON。
- 正式實作時 Astro 仍只讀取已驗證且狀態為 `published` 的資料。
- 不新增前端 API 呼叫、密鑰、後端服務或資料欄位。
- 本設計不改變 CLI、擷取、摘要、分類、保存與部署架構。

## Mockup 交付方式

- 提供三個互相獨立、可直接在瀏覽器開啟的 HTML mockup。
- 每個 mockup 應自帶完成視覺比較所需的 CSS，不依賴正式網站建置。
- 三個方案都必須實際展示完整 OG 縮圖，而非只以文字描述。
- A 方案作為正式實作參考；B、C 僅保留為設計比較材料。

## 驗收條件

- 三個 mockup 在桌面尺寸下能清楚呈現不同的視覺方向。
- A 方案在桌面、平板與手機寬度下沒有水平溢出或內容重疊。
- 所有 OG 圖都完整可見，沒有裁切、拉伸或變形。
- A 方案具備可辨識的鍵盤焦點狀態與合理的 HTML 語意結構。
- mockup 不修改正式首頁與摘要資料。
- 文件路徑、日期及內容與已核准的三部分規格一致。

## 後續工作

使用者審閱並核准本設計文件後，再建立正式實作計畫。正式首頁修改必須依 TDD 先加入會失敗的前端測試，再進行最小實作，最後執行前端測試、Astro 正式建置與 `git diff --check`。
