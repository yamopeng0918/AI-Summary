# AI Digest 結案報告影片設計

日期：2026-09-04
狀態：方向已核准，待使用者審閱書面規格

## 目的與觀眾

以 Hyperframes 製作一支面向課程老師與評審的 AI Digest 結案報告影片。影片必須同時證明產品完成度、技術深度與問題解決能力，讓觀眾在有限時間內理解專案解決的問題、完整工作流程、量化成果及開發者的學習收穫。

## 核心方向

- 片長：5～7 分鐘。
- 形式：全程簡報動畫搭配繁體中文旁白，不安排本人出鏡。
- 風格：科技產品發表；節奏俐落、資訊清楚，保留必要的驗證數據。
- 比例：成果展示約 60%，學習歷程約 40%。
- 主亮點：從輸入公開網址，到產生摘要、分類、保存並透過 GitHub Pages 公開展示的完整產品流程。
- 主要挑戰：將一般網頁、YouTube 與 Bluesky 三種來源整合到共同且可驗證的處理流程。

影片主題為：

> AI Digest：從公開網址到可驗證、可部署的 AI 知識摘要系統

## 敘事主線

影片以一次內容處理旅程串起所有資訊：使用者輸入公開網址，系統辨識來源、取得可用文字或逐字稿、產生繁體中文結構化摘要、執行分類、通過 Schema 驗證、保存 JSON，最後建置並部署到 GitHub Pages。

三種來源不是三段互不相干的功能介紹。畫面應先呈現共同主幹，再分支說明各來源如何取得文字，最後匯回共同的摘要、分類、儲存與展示流程。

## 時間與段落

1. **問題與目標（約 30 秒）**：說明資訊分散、閱讀耗時，以及將公開內容轉為可搜尋知識摘要的目標。
2. **完整成果流程（約 2 分鐘）**：展示輸入網址、來源辨識、擷取／逐字稿、AI 摘要、分類、JSON 與公開網站的端到端流程。
3. **三來源成果（約 1 分鐘）**：以一般網頁、YouTube 與 Bluesky 的實際成果卡片證明多來源支援；YouTube 補充字幕優先、無字幕才進行音訊轉錄。
4. **技術與量化證據（約 1 分鐘）**：呈現 180 筆人工審核資料、Accuracy 0.9167、Macro F1 0.9179、最大類基準 0.1667，以及自動化測試、建置與部署驗證。
5. **整合挑戰與解法（約 1～1.5 分鐘）**：說明來源差異、安全限制、共同 Schema、獨立解析器與失敗隔離；以無字幕轉錄及安全部署作為具體案例。
6. **成果與學習總結（約 30～45 秒）**：強調成品不是單次摘要展示，而是一套可重現、可驗證、可部署的完整產品。

總長目標為約 6 分鐘；剪輯可在 5～7 分鐘內調整，但不得犧牲完整流程或量化證據。

## 視覺與聲音規則

- 使用深色科技風背景、單一主色與高對比資訊卡；沿用 AI Digest 網站既有視覺作為品牌依據。
- 以流程線、來源圖示、摘要卡片、網站畫面與大型數字為主要視覺，不展示大量程式碼。
- 每個畫面只傳達一個重點；螢幕文字使用繁體中文短句，避免直接放入整段旁白。
- 動畫服務資訊層級：來源分支、流程匯流、數據強調與前後狀態轉換。避免無意義的裝飾性動態。
- 旁白語氣專業、自然且具主導感；不誇大 AI 能力，不宣稱未驗證成果。
- 背景音樂保持低音量科技感，不得干擾旁白；關鍵流程轉場可使用輕微提示音。

## 證據與內容邊界

影片只能使用 repository 與驗收紀錄中已有證據：三來源 MVP、正式分類模型、GitHub Pages、CLI、自動化測試及真實部署。核心數據以目前 `progress.md` 為準。

不得把 PDF／論文、OCR、登入或私人內容、完整討論串、網站後台及多使用者帳號描述為已完成功能。影片不得顯示 API key、Token、Cookie、`.env` 內容、私人路徑或其他憑證。

## Hyperframes 製作輸入與輸出

製作前整理下列素材：

- 約 6 分鐘的繁體中文旁白稿。
- 逐鏡表：時間、旁白、畫面、螢幕文字、動畫及素材來源。
- AI Digest 公開網站與三種來源成果的安全截圖或錄影片段。
- 流程圖、分類模型數據卡及測試／部署證據卡。
- 統一色彩、字體、轉場與字幕樣式。

Hyperframes 專案最終應輸出 16:9、1920×1080 的 MP4，包含繁體中文字幕與旁白。交付前必須檢查總長、字幕錯字、數字一致性、畫面可讀性、音量、轉場，以及所有畫面均未暴露敏感資訊。

## 成功標準

觀看完畢後，老師或評審應能清楚回答：

1. AI Digest 解決什麼問題。
2. 系統如何把三種公開來源轉為同一種可展示成果。
3. 哪些量化證據證明分類、測試與部署不是概念展示。
4. 跨來源整合遇到什麼困難，以及採取什麼設計解決。
5. 本專案的核心 MVP 已完成，而哪些功能仍明確屬於選配範圍。
