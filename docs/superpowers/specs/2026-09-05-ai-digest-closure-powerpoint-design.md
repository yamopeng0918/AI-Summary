# AI Digest 結案報告 PowerPoint 設計

日期：2026-09-05
狀態：方向已核准，待使用者審閱書面規格

## 目的與觀眾

製作一份面向課程老師與評審的 AI Digest 結案報告 PowerPoint。簡報須在 5～7 分鐘內清楚證明產品完成度、技術深度、量化成果與問題解決能力，並提供可直接照讀的繁體中文逐頁講者備註。

## 核心方向

- 形式：16:9 PowerPoint，約 9 頁。
- 敘事：成果導向，先展示完成品與完整流程，再以架構、數據、挑戰及驗證支持成果。
- 比例：成果展示約 60%，開發與學習歷程約 40%。
- 對象：課程老師與評審。
- 風格：科技產品發表結合編輯刊物感，資訊精準、畫面乾淨，不做密集儀表板。
- 主題：**AI Digest：從公開網址到可驗證、可部署的 AI 知識摘要系統**。

## 投影片結構

### 1. 封面

- 標題：AI Digest。
- 副標：從公開網址到可驗證、可部署的 AI 知識摘要系統。
- 畫面：AI Digest 網站代表畫面，保持極簡。
- 講稿目的：在 20～25 秒內說明專案核心價值。

### 2. 問題與專案目標

- 說明公開內容分散、閱讀耗時且難以整理。
- 定義目標：輸入公開網址，輸出可搜尋、可分類、可公開展示的繁體中文結構化摘要。
- 清楚標示核心 MVP 僅包含一般網頁、YouTube 與公開 Bluesky 單篇貼文。

### 3. 最終成果總覽

- 以一張實際網站畫面搭配三個成果重點：三來源、結構化摘要、GitHub Pages 公開展示。
- 強調成品不是單次 AI 示範，而是可重現的完整產品流程。

### 4. 三來源完整處理流程

- 以單一流程呈現：公開網址 → 來源辨識 → 來源文字取得 → AI 摘要 → 分類 → Schema 驗證 → JSON 儲存 → Astro 建置 → GitHub Pages。
- 一般網頁、YouTube、Bluesky 僅在文字取得階段分流，其餘匯回共同處理主幹。
- YouTube 明確標示字幕優先，無字幕才使用音訊轉錄。

### 5. 三來源成果展示

- 並列一般網頁、YouTube、Bluesky 的真實成果縮圖。
- 每種來源只保留一句差異說明，避免過度塞入技術細節。
- 展示摘要卡片或詳情頁，不顯示憑證、私人路徑或未公開資料。

### 6. 系統架構與技術選擇

- Python CLI：來源辨識、擷取、摘要、分類、驗證與保存。
- 獨立來源解析器：不同平台故障互不影響。
- 共用 Schema 與儲存層：驗證通過才寫入 JSON。
- Astro：只讀取已驗證且為 `published` 的資料。
- 前端不持有 API 金鑰，也不直接呼叫 AI 服務。

### 7. 分類模型與量化證據

- 180 筆人工審核資料，六類各 30 筆。
- Accuracy：0.9167。
- Macro F1：0.9179。
- 最大類基準：0.1667。
- 以大型數字和簡單比較視覺呈現，並說明模型結果明確高於基準。

### 8. 跨來源整合挑戰與解法

- 挑戰一：三種來源的文字取得方式不同。
- 解法：獨立解析器、共同資料契約及失敗隔離。
- 挑戰二：YouTube 可能沒有字幕。
- 解法：字幕優先，必要時音訊轉錄，並清理本機及遠端暫存資料。
- 挑戰三：公開部署不能洩漏憑證或不完整資料。
- 解法：Schema fail-closed、敏感資訊掃描與部署前驗證。

### 9. 驗證、部署、學習成果與結論

- 驗證證據：完整 Python 測試 715 passed、2 skipped；前端 Vitest 67 passed；Astro 正式建置與部署驗證通過。
- 部署成果：真實 GitHub push、matching workflow 與公開 smoke acceptance 已完成。
- 學習成果：從功能實作提升到資料契約、安全邊界、可重現評估與部署可靠性。
- 結論：AI Digest 已完成三來源核心 MVP；PDF、OCR、登入內容與網站後台仍為未實作選配範圍。

## 視覺設計

- 版型：16:9 寬螢幕。
- 色彩：沿用 AI Digest 品牌，以暖白為底、深墨綠／近黑為主字、珊瑚紅作重點色。
- 字體：使用可嵌入或系統可用的繁體中文字體；標題至少 35 pt，正文至少 16 pt，封面標題至少 50 pt。
- 圖像：優先使用 repository 與公開 GitHub Pages 的實際畫面；相同截圖不在多頁重複使用。
- 版面：每頁一個主要訊息，避免密集卡片、過多徽章及大段程式碼。
- 圖表：只使用能直接提升理解的流程圖與數據比較；其餘以畫面、短句及大型數字表達。
- 一致性：固定頁碼、標題位置、邊界與視覺層級，相鄰頁面輪替構圖但維持同一品牌語言。

## 講者備註

- 每頁均附繁體中文逐頁講稿。
- 全部講稿合計須支援 5～7 分鐘報告。
- 講稿補充因版面精簡而未放上投影片的脈絡，不逐字朗讀畫面文字。
- 語氣專業、自然、直接，不誇大 AI 能力，也不宣稱未驗證成果。
- 對數字、來源限制與未實作範圍使用一致說法。

## 內容與證據邊界

- 只使用 repository、`progress.md`、`todo.md`、核准設計規格與既有驗收紀錄中的可驗證成果。
- 不把 PDF／論文、OCR、登入或私人內容、完整討論串、網站後台及多使用者帳號描述為已完成功能。
- 不顯示 API key、Token、Cookie、`.env` 內容、私人路徑或其他憑證。
- 外部素材與非平凡主張須在對應投影片的講者備註加入 `[Sources]` 區塊。

## 輸出與驗證

- 最終輸出一份 `.pptx`，保存在 repository 的明確交付路徑。
- 使用 PowerPoint 相容方式建立，所有投影片均須可正常編輯。
- 交付前必須逐頁渲染成圖片並檢查：文字溢出、非預期重疊、錯誤換行、截圖裁切、圖表數字、字型、頁碼與視覺一致性。
- 執行投影片溢出檢查；未修正的非預期重疊或超出畫布不得交付。
- 驗證每頁講者備註存在，且總講述時間可控制在 5～7 分鐘。
- 同步更新 `progress.md` 與 `todo.md`，只記錄已實際完成並通過驗證的結果。

## 成功標準

報告結束後，老師或評審應能清楚回答：

1. AI Digest 解決什麼問題。
2. 系統如何把三種公開來源轉成共同且可展示的成果。
3. 哪些分類、測試與部署數據證明它不是概念展示。
4. 跨來源整合遇到什麼困難，以及如何解決。
5. 開發者從專案中學到什麼。
6. 核心 MVP 已完成哪些內容，哪些功能仍不在完成範圍內。
